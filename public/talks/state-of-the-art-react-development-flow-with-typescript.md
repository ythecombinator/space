"TypeError: Cannot read property n of undefined" errors shouldn't follow your code and avoiding them with TypeScript shouldn't bring verbosity or too many type annotations There are ways of making your typings concise and reducing boilerplate with stuff like type inference, control flow analysis, and a few TypeScript libraries. In this talk, I'll present a few recipes on how to use React (and part of its ecosystem, like Redux) in a functional way with TypeScript to make your code completely type-safe according to our new "declare once, infer everywhere™" philosophy.
